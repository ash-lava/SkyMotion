SKYMOTION 2.0.4 — RESTORE THE REFERENCE SKY ATLAS

1. Open the supplied pull request on GitHub while signed in as ash-lava.
   Scroll down, select Merge pull request, then Confirm merge.

2. Let Render auto-deploy main. If automatic deployment is off, open:
   Render Dashboard > SkyMotion > Manual Deploy > Deploy latest commit.

   Build and start commands stay the same:
   pip install -r requirements.txt && python -m unittest -q test_server.py
   uvicorn server:app --host 0.0.0.0 --port $PORT

   One added dependency, astropy-healpix, installs automatically from
   requirements.txt. Include the new hips_survey.py in the checkout.
   Keep SPHEREX_COLLECTIONS=spherex_dr1. No API key or new setting is needed.

3. Open https://skymotion-sk2p.onrender.com/api/health
   Wait until the version is 2.0.4, then hard-refresh the app.
   Windows/Linux: Ctrl+Shift+R. Mac: Command+Shift+R.

4. Select Sky atlas. You should see real M101 reference imagery.
   Try DSS, 2MASS and WISE from the survey selector, then drag or zoom.
   On a phone, the layers icon opens survey selection.

   Direct atlas link:
   https://skymotion-sk2p.onrender.com/?mode=atlas

5. Select SPHEREx sequence and load exposures to check that feature too.
   The default home page still starts its live M101 SPHEREx search.

The new atlas uses IRSA's public reference-survey tiles and the built-in map.
It no longer loads the broken CDS map-script or HiPS2FITS service addresses.
Reference-survey images are distinct from dated SPHEREx science exposures.
Both paths fetch real archive data. There is no saved demonstration sequence.

A healthy /api/health means the app server is running; it does not guarantee
that an external data provider will answer every request. If an image fails,
use Retry map and save the exact error plus the coordinates and survey.

HOW_IT_WORKS.txt explains the entire system in beginner-friendly language.
VALIDATION.txt records what was tested and which checks used live services.
