CHANGE
The atlas uses the existing built-in map directly and requests its images
from the same-origin /api/sky.jpg API. The server downloads real public IRSA
survey tiles, projects them to the requested north-up/east-left ICRS TAN grid,
and returns a JPEG. No external map script, WebGL or CDS HiPS2FITS request is
needed. Existing drag/pan, zoom, survey selection and grid controls remain.
The live SPHEREx archive search and FITS processing logic is unchanged.

The renderer uses Astropy HEALPix, added to requirements.txt, and follows
IVOA HiPS 1.0 JPEG tile orientation: even nested bits select rows, odd bits
select columns. It samples nearest tile pixels, so this remains a reference
map rather than a flux-conserving science reduction.

Resource bounds: at most 12 tiles per view, at most four concurrent tile
requests, 1.5 MB per tile download, strict 512 x 512 JPEG validation, 16 MB
tile cache, 20 MB finished-image cache, one reprojection at a time and 64-row
coordinate strips. A request needing too many tiles uses a lower tile order.
Only fixed IRSA survey paths are downloaded. Failed tiles are not cached.

LIMITS
Live success was verified locally against IRSA, not after deploying the new
code to Render. External archive failures remain possible. The atlas shows
reference composites from older surveys; live retrieval is not a live camera
feed. It does not supply new SPHEREx epochs. Reprojection cannot add angular
resolution and nearest-pixel sampling is unsuitable for calibrated photometry.

SPHEREx still returns a limited live sample of 16 or 4 records per collection;
that is not a complete survey inventory. Independent display stretches,
center wavelength changes, processing differences and flags can imitate
variability. All five challenge targets are not claimed as verified here.
The optional Sesame and Gaia services were not revalidated in this change.
